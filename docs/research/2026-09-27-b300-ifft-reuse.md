# B300 public-weight inverse FFT reuse — 2026-09-27

**Not promoted.** A cold full Mamba-3 pair improves **148.32 → 144.10 s
(2.85%)**, while the prefix improves 3.39%. Exactness and model gates pass,
but the result falls short of the predeclared 5% promotion threshold. The

The question is whether reusing the **unscaled inverse FFT** of immutable
public weight masks reduces the preparation wait remaining after the
[two-worker pipeline](2026-09-27-b300-parallel-prefetch.md). The previous
[final-coefficient cache](2026-09-25-weight-coefficient-cache.md) did not
reuse efficiently across levels. This trial retains the qualified two-worker
baseline; the later fused RNS/NTT completion experiment is not enabled.

## Mechanism and invariants

For a fixed public weight mask and CKKS geometry, the inverse transform
precedes every level-dependent scale, rounding and residue conversion.
Store that transform once, then copy it into the encoder's private working
vector on subsequent uses. All later operations still execute in the pinned
OpenFHE implementation. No approximation, floating-point operation order,
model polynomial, ciphertext layout or refresh circuit changes.

The cache key contains a stable frozen weight-node identity, input columns,
BSGS diagonal, cyclotomic order, vector length and floating-point rounding
mode. The DAG's nodes and weights remain immutable throughout evaluation.
Only the shared packed evaluator's public replicated-linear operands use
this API. Activations, client encoding, refresh and other transforms pass
through the original function. Mamba-2/3 share the helper.

An explicit `FHE_STAGE0_IFFT_CACHE` CMake option enables a GNU/LLVM ELF
`--wrap` bridge to the pinned static OpenFHE inverse-FFT symbol. A thread-local
RAII scope confines a cache lookup to one public-weight encode, restores any
outer scope on exceptions, and verifies that exactly one supported FFT call
was reached. This avoids copying the CKKS encoder's scale/rounding/metadata
implementation. Unsupported static linkage fails clearly when the option is
used. The bridge is a pinned Linux backend facility, not a portable OpenFHE
API or a replacement for the transform's mathematics.

The cache retains a first-admitted subset, without eviction or speculative
prefilling. `--ifft-cache-mib 4096` bounds retained numeric values and in-flight
reservations to 4 GiB. Map/allocation overhead and caller working vectors are
additional; process RSS is measured separately. Miss computation happens
outside the map mutex, immutable results may be read concurrently, and
duplicate concurrent misses release the unused reservation. Capacity misses
execute the original FFT. The first fill occurs inside evaluation and is
included in the cold request comparison.

## Qualification and comparison

The CPU cache tests exercise owned-result isolation, geometry/diagonal/source
separation, capacity bypass, exception cleanup and racing equal-key misses.
All 23 native CPU tests, 33 Python runner tests and the cache ASan/UBSan check
pass. ThreadSanitizer is not rerun after its preceding environment startup
failure; no TSan coverage is claimed.

Four fresh GPU probes check **960 exact RNS/metadata cases** and **36 encrypted
primitive cases** across Mamba-2/3 configurations and rings 32,768/65,536.
Both small/full packing, six levels, degrees 1/2, compact/fallback paths and
cache hits/misses are reached. Each probe reports 226 hits and 23 misses,
including the encrypted operations. Reference encodes run without a cache
scope. Coefficient equality checks every RNS limb, not just decoded error.

The model gate uses one new prefix A/B pair. A reduction above 0.5% permits
one new full A/B pair. The adoption criterion is at least 5% full reduction,
all existing accuracy/token/work-count gates and the configured memory bound.
These gates were recorded before model timing. There is no automatic extra
ABBA or selective sample removal, following the user's preference to move on
from repeated timing. A single pair has a narrower measurement basis than
the preceding 37.20 s/token ABBA result.

Both arms use the same B300 GPU 4, CPU mask 64–68, NUMA node 2, four OpenMP
threads, two producers and two-item admission window. The common measurement
helper initializes each producer's OpenMP region before pinning it to CPU
65/66; observed native main placement is CPU 64. This helper is retained in
the measured sources and is absent from the portable product sources.
Host clocks, governors and unrelated GPU jobs are not changed.

Mamba-3 SISO 187M remains 12 layers, five encrypted evaluations and four
generated tokens, ordinary ring 32,768 and refresh ring 65,536, depth 44,
scale 59/first modulus 60, two-pass S2C-first refresh, and experimental
`security=not-set`. Both model error gates stay 0.001 and expected full IDs
are `[315,279,1614,315]`. No full Mamba-2 performance or new security level is
claimed. Input files and all five static library identities are freshly
rechecked before qualification.

| Peak process RSS | 26.29116 GiB | 26.33359 GiB |

The candidate admits **10,248** transforms and reuses them **40,992** times
(an 80% hit rate), with no capacity bypass. Retained numeric data is
**2,686,451,712 bytes (2.502 GiB)**. This verifies level-independent reuse;
the remaining limitation is not the level-specific miss problem from the
older final-coefficient trial. The process peak rises only about 43.45 MiB;
that is a different metric and does not negate the 2.50-GiB retained cache.

CPU encoding service falls 10.12 seconds, preparation wait falls 4.65 seconds,
and evaluation falls 4.22 seconds. The candidate's observed **36.02 s/token**
is a single experimental result, not the adopted performance claim. Its
maximum polynomial-reference error is 4.1535e-7 and exact-reference error is
4.7235e-5, below both unchanged 0.001 gates. All generated IDs, operation
counts, levels/scales and refresh settings pass the independent comparison.

**Decision:** preserve the experiment without promoting its extra memory and
backend-specific integration for this measured effect. The five-percent
threshold is this trial's engineering criterion, not a statistical test or
a claim that a 2.85% improvement has no value. No extra repetitions or full
prompt changes are used to seek a larger number.

CPU encoding service overlaps other workers and GPU execution. It cannot
be added to preparation wait or treated as an independent wall-time saving.
Evaluation excludes setup and client verification; complete process wall
time is reported separately. No new Nsight GPU-utilization claim is made.
