# SlotsToCoeffs-first GPU refresh

This study implements one circuit from the
[first-principles review](2026-09-25-first-principles.md): move SlotsToCoeffs
before modulus raising, then use a single real modular-reduction branch.
The decision is **retain as an opt-in experimental path**. The matched
12-layer run improves from **759.7043 to 747.6291 seconds (1.59%)**, preserves
all numerical/token gates, and reduces peak process RSS by **1.11 GiB**.
This is a modest full-model gain, not the large reduction suggested by the
isolated primitive. The existing circuit remains the default.

The [evidence directory](../../results/dgx/2026-09-25/s2c-first/) records the
comparison contract, sources, independent processes, and rejected boundary.
The baseline is the released ready-node scheduler, not the earlier sequential
executor. All model weights, frozen nonlinear coefficients, public bounds,
and client feedback remain fixed. The numerical gates remain 0.001 against
both exact FP64 and the frozen polynomial circuit, with the same token IDs.

## Circuit and level accounting

The baseline full-real FIDESlib circuit raises the modulus, performs
CoeffsToSlots, evaluates modular reduction on two internal components, then
performs SlotsToCoeffs. The candidate performs SlotsToCoeffs at low modulus
first. This permits one real modular-reduction component after raising and
CoeffsToSlots. The outer two-pass residual correction is retained, including
its multiplier of 4096. Removing the second internal component from the old
ordering would be incorrect.

The ordering follows OpenFHE's
[v1.5.0 documentation](https://github.com/openfheorg/openfhe-development/blob/v1.5.0/src/pke/examples/CKKS_BOOTSTRAPPING.md)
and its
[reference implementation](https://github.com/openfheorg/openfhe-development/blob/v1.5.0/src/pke/lib/scheme/ckksrns/ckksrns-fhe.cpp).
This port retains the pinned FIDESlib/OpenFHE fork. Its `modevallevels`
precomputation override selects the low-modulus decoding matrices; it is not
the upstream `BTSlotsEncoding` Boolean. The uniform-ternary modular polynomial
and the existing correction-factor policy are unchanged.

FIDESlib also defers an affine-transform rotation across the old pair of
transforms. The port records that offset and restores each transform's
boundary with an input/output rotation when the order changes. This adds
rotation-key material. Reusing the old matrices with a different call order
without these corrections would not implement the intended circuit.

OpenFHE levels count consumed primes. At degree one, the new primitive
requires an input level of at most 39; its four initial transform stages
and scale adjustment need six primes. The second residual pass costs another
level. The production wrapper also needs masking/normalization space.

| Policy | Existing circuit | S2C-first |
| --- | ---: | ---: |
| Planner's consumed-level ceiling | 39 | 35 |
| Two-pass output level, noise degree 2 | 22 | 18 |
| Planner's usable interval | 17 | 17 |

The initial fresh ciphertext reaches refresh sooner. After refresh, the new
circuit retains four additional primes for ordinary arithmetic. Equal usable
depth therefore does not imply equal ordinary-operation cost.

## Small encrypted checks

Every run uses Spark GB10, ring degree 65,536, 32,768 slots, depth 44,
59-bit scaling, first prime size 60, uniform ternary, three large digits,
FLEXIBLEAUTO and transform budgets [4,4]. CPU affinity is 15–19 and
`OMP_NUM_THREADS=4`. The existing `security=not-set` qualification is retained.
These are not newly validated 128-bit parameters.

The standalone probe explicitly reproduces both correction passes. It tests
all slots with positive/negative constant blocks, alternating ±1, small
values near zero, and deterministic random values. Inputs are encrypted
again for each sample; decryption and verification are outside the timer.

| At input level 36 | Existing circuit | S2C-first |
| --- | ---: | ---: |
| Warm two-pass times, seconds | 1.30926, 1.31371 | 0.80150, 0.79966 |
| Maximum two-pass absolute error, including first sample | 2.078e-7 | 4.660e-7 |

The warm primitive is about 39% shorter in this small sample. The standalone
error is slightly larger and remains below the unchanged threshold. Inputs
at consumed levels 8 and 38 also pass. A two-pass input at level 39 correctly
fails when its residual reaches level 40; it is preserved as a rejected case,
not counted as a successful sample.

The one-layer, three-evaluation ABBA comparison uses the same prototype
binary with the circuit selected explicitly. All four runs pass both error
gates and produce [6864, 6864].

| Prefix metric | Existing circuit, mean | S2C-first, mean |
| --- | ---: | ---: |
| Evaluation seconds | 39.1143 | 38.5950 |
| Refresh seconds, including wrapper | 11.1554 | 7.1621 |
| Backend bootstrap calls | 16 | 16 |
| Ciphertext products | 673 | 673 |
| Ciphertext/plaintext products | 5,425 | 5,435 |
| Model/wrapper rotations, excluding bootstrap internals | 2,548 | 2,560 |

The total reduction is only **1.33%**. Other evaluation work increases by
about 3.47 seconds, offsetting most of the approximately 3.99-second refresh
saving. The larger retained modulus and changed scheduling make the full
comparison necessary. A progress update initially attributed this to more
bootstrap calls; the completed counters above correct that inference.

## Integration and limits

Final-source qualification uses separate executables: the unchanged released
baseline and the new candidate. Their final prefixes take 38.6702 and 38.1441
seconds and pass before the full runs start. Full inference uses all 12 layers,
five evaluations and four generated IDs [315, 279, 1614, 315].

| Full-model metric | Existing circuit | S2C-first |
| --- | ---: | ---: |
| Native evaluation, seconds | 759.7043 | 747.6291 |
| Process wall time, seconds | 801.7807 | 788.0360 |
| Refresh including its wrapper, seconds | 363.5271 | 248.5270 |
| Other evaluation work, seconds | 396.1772 | 499.1021 |
| Backend bootstrap calls | 476 | 484 |
| Logical refreshed values | 1,331 | 1,335 |
| Ciphertext products | 12,005 | 12,005 |
| Peak process RSS, GiB | 27.3141 | 26.2067 |
| Maximum exact-reference error | 1.14581e-4 | 4.68984e-5 |
| Maximum frozen-polynomial error | 8.66091e-5 | 5.61686e-7 |

Refresh saves **115.00 seconds**, but other work grows by **102.92 seconds**.
Without double-counting nested timers, ordinary routing increases by 42.55 s,
linear maps by 32.34 s, polynomials by 24.72 s, and other work by 3.32 s.
Host encoding's 152.01 → 183.14 s is included in those categories.
The lesson is to optimize total time per useful computation interval, including
the cost of retained primes, rather than bootstrap latency alone.

Both modes have zero intermediate evaluator decryptions and pass both 0.001
gates. The smaller observed candidate error is a result for this workload and
fresh key pair, not a general precision or long-context guarantee. There is
one final full run per mode; the prefix controls corroborate a small gain,
not a statistical latency distribution. Setup, payload parsing and final
client validation are outside the native evaluation timer; process wall time
is reported separately.

The candidate is opt-in through `--s2c-first`, requiring planned, grouped,
two-pass refresh. The scheduler and routing paths share the configured level
limits. Builds without the backend patch retain the existing execution path
and reject the new flag before evaluation.

The backend port currently supports uniform-ternary, full-real packing,
FLEXIBLEAUTO and [4,4] budgets. Other configurations must omit the flag;
requesting the new mode for them raises an error. GPU context serialization rejects S2C-first before writing:
the pinned serializer does not preserve this circuit-mode metadata.
Long-context behavior and arbitrary-prompt quality are outside this fixed
payload comparison. The Mamba-2 executor is not switched to this circuit.
The two correction passes remain enabled; this study does not qualify a
single-pass S2C-first refresh.

Rebuild with [the Spark instructions](../dgx-spark.md#build), then add
`--s2c-first` to the existing packed Mamba-3 command alongside
`--planned-refresh --batch-refresh --frontier-refresh`. The Python
`experiments/run_packed_probe.py` runner also accepts the flag and records it.
The evidence directory contains exact measured commands, payload manifests,
source overlays and the standalone probe. Reconstruct the pinned FIDESlib
checkout before applying the overlays; they do not vendor CUDA or OpenFHE.

Validation passes 290 Python tests, including 19 C++ contracts, both Ruff
checks, all native GPU-linked build targets, and a build against the older
backend API. That older build rejects the new flag before reading the payload.
The delivered backend patch reconstructs the measured backend byte-for-byte.
