# B300 classical-128 prototype and public-operand preparation

The frozen, twelve-layer Mamba-3 SISO 187M request completes with a
classical-128 CKKS parameter audit. It evaluates five encrypted steps and
generates the same four IDs, `[315, 279, 1614, 315]`, with both original `0.001`
error gates and zero evaluator decryptions.

The initial secure baseline takes **327.508 seconds**. Compact GPU expansion
of additive plaintexts plus a 2,048-entry mask cache reduces it to
**235.750 seconds (28.02%)**, or **58.94 seconds per generated token**.
There is one full sample per setting, excluding setup and final validation;
it is not a steady-state latency or statistical-significance claim.

## Parameter qualification

The profile is opt-in: `--security 128-classic --security-digits 4`.
Its single ring has dimension 131,072 and 65,536 slots. Depth 44, 59-bit scale
primes, the 60-bit first prime, two-pass S2C-first refresh, even bootstrap seed,
model weights/polynomials and token/error gates remain fixed. The experimental
dual-ring bridge is rejected in this mode.

The [shared context audit](../../native/fideslib_stage0/src/fideslib_security.hpp)
requires the library's `HEStd_128_classic`, uniform ternary secret, HYBRID
key switching and Gaussian sigma at least 3.19. It checks the **actual maximum
Q times P**, including auxiliary key-switch primes, before key generation and
again after evaluation. It uses the published
[2024 Security Guidelines, Table 5.2](https://cic.iacr.org/p/1/4/26/pdf),
whose classical-128 bound is 3,523 bits at N=131,072 for these assumptions.
The older draft's different limits are not used.

| HYBRID digits | Q towers / bits | P towers / bits | Actual QP bits | Result |
| ---: | ---: | ---: | ---: | --- |
| 4 | 45 / 2,656 | 12 / 720 | 3,376 | Pass |
| 5 | 45 / 2,656 | 9 / 540 | 3,196 | Pass |
| 6 | 45 / 2,656 | 8 / 480 | 3,136 | Pass |

The parameter probe rejects N=65,536 with three/four/six digits and N=131,072
with three digits. Unsupported security labels and sparse-secret assumptions
also fail. The Python runner independently validates the returned audit and
rejects missing evidence, the wrong bound, changed ring assumptions or a
different requested digit count.

This establishes the classical RLWE parameter profile of this prototype.
The existing inline client decrypts final hidden vectors for greedy feedback;
process separation, output-security analysis and arbitrary-prompt model quality
remain separate work. Earlier `security=not-set` results do not acquire this
qualification retrospectively. Full trained Mamba-2 execution under this
profile has not been measured.

## What changed in ordinary evaluation

`--gpu-addend-rns` extends the shared compact plaintext path to scale-degree-two
addends. The pinned OpenFHE encoder first rounds degree-one coefficients,
then multiplies residues by its rounded scale factor. We retain the same
degree-one signed coefficients and do that exact modular multiplication on
the GPU before NTT. Shoup reduction avoids a per-word integer division.
This removes CPU expansion and transfer of every modulus tower; the encoded
values, scale metadata and ciphertext computation stay the same.

The compact path requires full packing, one GPU, supported 64-bit moduli,
FLEXIBLEAUTO and a proven signed-lift range. Sparse packing, large values,
the last tower and other scale degrees retain the existing fallback. The
default remains off, and `--gpu-plaintext-rns` is required.

`--plaintext-cache-capacity N` exposes the existing bounded mask cache's
capacity. It requires `--cache-plaintexts`; the default remains 64. Keys
include exact value bits and consumed level, and hash collisions still require
an exact comparison. Dense weight diagonals bypass this cache. Increasing
capacity uses GPU and host memory, so it is a hardware-dependent option.

The two preparation changes share the existing encoder used by both models.
Across real/complex configurations and N=32,768/65,536/131,072, all **2,160
exact RNS cases and 54 encrypted arithmetic cases** pass. Each case compares
against the ordinary OpenFHE representation, including fallbacks and padding.
The secure refresh qualification separately covers 15 width/level combinations,
15 following products and 60 rotations per digit configuration at `1e-6`.

## Comparisons

All timing arms use B300 GPU 4, the same patched FIDESlib/OpenFHE libraries,
CPU/NUMA placement and two ordered preparation workers. Each process starts
with fresh keys and a cold plaintext cache. GPU jobs and builds are serialized.
Completion hooks start dependent jobs and preserve their exit status.

| Prefix option | Evaluation seconds | Cache hits / misses |
| --- | ---: | ---: |
| Control, 64 entries | 18.2690 | 421 / 1,211 |
| GPU addends, 64 entries | 16.0758 | 421 / 1,211 |
| Original addends, 1,024 entries | 16.2582 | 1,186 / 446 |
| GPU addends, 1,024 entries | 14.1853 | 1,186 / 446 |

The first full combination changes 24,916 cache misses to 8,213 and records 1,935
compact degree-two encodes. Host encoding falls 180.38 to 107.32 seconds,
and upload falls 18.88 to 9.48 seconds. These timers overlap other work and
must not be added to reconstruct elapsed time. Refresh uses the same 484 calls
and circuit; its observed time rises 79.20 to 83.49 seconds. The whole-evaluation
gain, rather than a claimed refresh speedup, is the adoption evidence.

That candidate's maximum exact/polynomial errors are 4.746e-5 / 7.881e-6.
Setup takes 139.97 seconds, separate from evaluation. The two-worker CPU
affinity helper is a common measurement-only patch, not a portable product
default. Sampled GPU memory and CPU placement are retained with the results.

Five/six HYBRID digits also pass their refresh gates, but their separate
prefix evaluations are 18.293/18.655 seconds versus 18.388 seconds for four.
The best change is only 0.52%, below the 3% screen for another full run.
Four digits are retained.

After qualification, a second full run raises the cache to 2,048 entries.
Evaluation falls **244.401 → 235.750 seconds (3.54%)**, passing the 2% screen
for retaining the additional memory. Misses fall to 5,151, and maximum
exact/polynomial errors are 4.700e-5 / 4.166e-6. All circuit counts, token IDs
and security-audit fields match. Host encoding is 99.75 seconds, upload 8.43
seconds, preparation wait 24.17 seconds and setup 136.74 seconds. Refresh is
85.96 seconds: the circuit is preserved, but refresh latency is not improved
in this comparison.

Sampled device memory rises **130.41 → 173.41 GiB**, while peak process RSS
rises **61.19 → 66.62 GiB**. Device samples are five seconds apart and are not
an exact allocation high-water mark. The full processes observe the main
thread on CPU 64 and preparation workers bound to 65/66. Two prefix processes
have a sample on another permitted CPU during their first second, before
runtime initialization; later observations use CPU 64. These startup samples
are retained, not discarded as evaluation noise.

## Remaining cost and stopping point

A new Nsight prefix with the 1,024-entry setting records 15.48 seconds of
instrumented evaluation and 4.39 seconds of unioned GPU activity. The 190,072
kernel durations sum to 5.75 seconds because kernels overlap. Neither number
is SM utilization or a bound on obtainable speedup. Synchronization API time
includes necessary GPU execution. CPU leaf samples still include FFT,
coefficient fitting and client-side encryption/NTT; the largest device kernels
are NTT and key switching. The trace and CPU sample summaries are retained.

The capacity sweep stops at 2,048. At least 2,048 misses are compulsory, so
at most 3,103 remaining cache misses could be eliminated by capacity alone.
Extrapolating the preceding pair's net time per avoided miss gives about
8.77 seconds (3.72%) even if all those reloads disappear. That time is a
heuristic estimate, not a theoretical lower bound. A conservative 3,072-entry
memory estimate reaches 269,730 MiB, above the study's 247,536-MiB headroom
screen. Smaller increments have no clear material gain for this cold request.

Five/six digits have already screened out. The earlier inverse-FFT-result
cache saved only 4.22 seconds on a similarly costly linear path; that historical
result does not establish a material secure-context gain. Another kernel tile,
level-aware scheduling, slim-polynomial adaptation and coefficient-domain
layouts need new designs and qualification. This stops the current measured
cycle, not a claim that encrypted inference has reached its limit.

## Reproduction and evidence

The [curated artifacts](../../results/b300/2026-09-27/security128/README.md)
include raw results, every job's command/exit state, source snapshots, the
recorded validation and preserved negative/superseded attempts. Model inputs
are freshly hash-checked, and the final 96 native source files match their
measured source snapshot byte-for-byte. Local checks pass 331 tests and Ruff;
the later paper-screen helper is separately reproduced against the frozen
program. A reporting-only parameter-probe revision marks GPU allocation
telemetry as unavailable, replacing an unmeasured constant, and is rebuilt
and rerun without changing the parameter decisions.

Build the [parameter and refresh probes](../../experiments/security128/README.md)
against the adopted [rotation/refresh backend](2026-09-27-b300-rotation-stream-chain.md)
and the inverse-FFT-patched OpenFHE core. Retain the exact dependency commits,
patches, library hashes and source snapshots in the study's artifacts.

The optimized packed command adds these options to the existing frozen model
runner, removing `--gpu-dual-ring`:

```text
--security 128-classic --security-digits 4
--gpu-addend-rns --cache-plaintexts --plaintext-cache-capacity 2048
```

The complete command also retains planned/batched/frontier refresh, S2C-first,
GPU plaintext RNS/NTT, two-worker preparation, rotation/basis sharing and the
existing ownership/upload flags. Use the recorded job commands rather than
interpreting this short option excerpt as a standalone invocation.

The [Sylph/Cachemir review](2026-09-27-sylph-cachemir.md) records separate
algorithmic opportunities. Its sampled algebra checks and static packing
counts are design evidence, not additional encrypted speedups.

The original study verified all 243 exported evidence files and the numerical
acceptance checks. Public derivatives now use the shared publication manifest;
see the [experiment workflow](../experiments.md) for verification and inspection.
