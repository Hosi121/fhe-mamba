# B300 profiling and an exact inverse-FFT plan

Precomputing OpenFHE's public inverse-FFT lookup sequence reduces full
Mamba-3 evaluation on B300 from **266.22 to 234.84 seconds (11.79%)** in a
four-process ABBA comparison. The complete container-run mean falls from
365.59 to 342.45 seconds (6.33%). The optional shared dependency patch is
adopted, with unchanged model, refresh and numerical/security settings.
[Raw evidence and the comparison tool](../../results/b300/2026-09-26/nsight-ifft/)
include the initially negative, noisy prefix block as well as the full controls.

## What the profilers show

The frozen one-layer, three-evaluation workload runs on B300 GPU 4 with
four OpenMP threads, CPU set 64–68 and NUMA node 2. Nsight Systems **2025.5.1**
captures the application's `cudaProfilerStart` / `cudaProfilerStop` evaluation
range with CUDA tracing and CPU samples. Its instrumented evaluation takes
15.7757 seconds, including 7.3734 seconds recorded in host plaintext encoding.
The inverse FFT is the largest resolved leaf symbol: 1,262 samples out of
7,659 on the dominant application thread. These are sample counts, not wall
seconds; some parent backtraces are incomplete.

There are 308,734 traced GPU kernel instances, totaling 2.85925 seconds of
kernel duration. The union of kernel, copy and memset intervals is 2.54483
seconds, because separate streams overlap. The two leading NTT variants total
1.00029 seconds. Host-to-device copies total 0.14141 seconds on the GPU.
CUDA calls include 54,601 device synchronizations and 310,311 kernel launches.
These instrumented numbers identify work; they are not unprofiled performance
controls and their categories must not be added as a wall-time partition.

Nsight Compute **2025.3.1** profiles the first four matching NTT launches inside
the evaluation range, collecting SpeedOfLight, LaunchStats, Occupancy and
MemoryWorkloadAnalysis with kernel replay. Clocks remain under normal driver
control. The four durations are 25.79–32.29 microseconds, SM throughput
42.49–48.15%, achieved occupancy 44.19–44.80%, DRAM throughput 0.23–11.72%, and
waves per SM 0.79–0.95. These selected launches do not saturate HBM bandwidth;
they do not characterize every NTT level or establish a GPU-kernel speedup.

The original Nsight Systems 2025.1.3 attempt runs inference successfully but
produces no report. Its failed instrumentation record is preserved. The
2025.5.1 CLI is downloaded directly to the task directory and checksum-verified;
no host package, driver, clock or global profiling-permission setting is changed.
Profiler containers receive task-local capabilities and are removed afterward.

Tool semantics: [Nsight Systems guide](https://docs.nvidia.com/nsight-systems/UserGuide/),
[Nsight Compute profiling guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/).

The earlier unprofiled full B300 run records 144.333 seconds of encoding out
of 265.159 seconds (54.4%). Eliminating that entire category would bound its
possible saving, but this patch addresses only the inverse FFT within it.
The FFT's full-model wall-time fraction was not separately timed; CPU sample
fractions and the isolated twofold speedup cannot establish that fraction.

## The implementation and its boundary

For each power-of-two stage length `len`, the original inner butterfly loop
computes

```text
idx = (4*len - (rotation_group[j] % (4*len))) * (cyclotomic_order / (4*len))
```

and loads a complex twiddle. Both depend only on public geometry and `j`.
The patch copies those **same table entries** into contiguous stage arrays at
initialization. A stage of length `len` starts at offset `len/2 - 1`; the
geometric sum needs `slots - 1` complex doubles for all stages. The two model
geometries add 786,400 bytes of numeric tables, plus vector/map overhead.
Their construction remains inside request setup.

At 16,384 slots, the original transform performs 114,688 inner twiddle-index
calculations. The plan prepares 16,383 entries once per geometry and then
reads them directly on every call. Stages occupy consecutive ranges
`[len/2 - 1, len - 2]`; a smaller power-of-two transform uses the same stage
ranges. Copying the existing trigonometric table avoids recomputing twiddles
with a potentially different floating-point rounding path.

The hot loop retains the original butterfly order, complex multiplication,
NaN behavior, bit reversal and normalization. CKKS scaling, rounding, residues,
GPU upload, refresh and ciphertext arithmetic are untouched. No fast-math,
new ISA requirement, model-weight cache or transformed-input cache is added.
Unsupported plan geometries retain the original loop. Existing initialization
serialization also governs creation of the immutable table.

This is a shared OpenFHE change, independent of the Mamba variant. Mamba-2's
complex configuration is covered by the exact encoder checks. This study does
not measure full Mamba-2 speed or claim performance on DGX Spark.

The measured candidate replaces only `dftransform.cpp.o` in an isolated copy of
the existing static core archive, then relinks the original native objects.
The baseline executable is copied unchanged. The FIDESlib library, CUDA code,
other OpenFHE archive members, model files and native options stay fixed.
The full source revisions, compile/link commands and hashes are retained.
For ordinary builds, apply the [dependency patch](../../native/fideslib_stage0/patches/openfhe-v1.4.2-inverse-fft-plan.patch)
to an isolated pinned OpenFHE source, install into a new prefix, and rebuild
FIDESlib and the native executors against it. `LD_LIBRARY_PATH` cannot change
a statically linked FFT. See the [qualification instructions](../../experiments/openfhe_ifft/README.md).

## Exactness and the small experiment

The actual baseline and candidate library functions run in separate processes.
All **249 inverse-FFT cases** match bit-for-bit, covering both cyclotomic orders,
every power-of-two length through 32,768, signed zeros, dense/sparse/alternating
inputs, subnormals, large finite values, infinity, a NaN payload and an
uncached geometry. The 1,572,836-word stream is checked through EOF.

Actual `MakeCKKSPackedPlaintext` calls match **251,658,240 integer coefficient
words** and all recorded metadata. Rings 32,768/65,536, real/uniform-ternary and
complex/sparse-ternary contexts, 512/full packing, levels 0/21/34, degrees 1/2,
and zero/dense/sparse/large/tiny inputs are covered. All 192 encodes and 48
expected small-scale exceptions agree. Golden streams are retained on the
measurement host with sizes and hashes; they are not copied into Git.

An independent-process ABBA microbenchmark restores inputs before each of
128 timed transforms. At 16,384 slots the mean is 0.73854 → 0.38618 ms;
at 32,768 slots it is 1.59095 → 0.75881 ms. This measures the transform with
initialized tables. It excludes context setup and is not a model-speed claim.

## Model comparison protocol

Both variants use fresh processes, fresh keys, the same pinned CUDA 13 image,
GCC 13.3 and `-O3`, one B300, unchanged CPU/NUMA affinity, and four OpenMP
threads. Builds and timed GPU comparisons do not overlap. Inputs are the
existing hash-bound trained Mamba-3 SISO 187M payloads; no new fit or checkpoint
is selected. Ring sizes 32,768/65,536, depth 44, scale 59/first modulus 60,
two-pass S2C-first refresh and experimental `security=not-set` stay fixed.
Both numerical gates remain `0.001`, with unchanged generated IDs, operation
counts and zero evaluation/debug decryptions.

The first prefix ABBA has substantial baseline variation: **9.64156, 12.52129,
12.41527, 13.77588 seconds** in A/B/B/A order. Its mean rejects the candidate
by 6.49%, despite identical outputs and faster isolated FFTs. A single additional
unchanged ABBA is therefore allowed to examine the variance. All eight samples
enter the qualification mean; the first four are not discarded. A mean prefix
reduction above 0.5% permits exactly one four-process full ABBA comparison.
No CPU binding, worker-wait, encryption or accuracy setting changes for this
extension. The eight-prefix mean is **12.86257 → 12.43327 seconds (3.34%)**,
which passes that gate. The baseline variation remains a limitation; this
mean is not a statistical-significance claim.

Full controls cover 12 layers, five encrypted evaluations and four generated
tokens from `The capital`, with expected IDs `[315, 279, 1614, 315]`.
Native evaluation and complete container-run time are reported separately. Rates per token are
amortized over this request, not steady-state decode latency. External network
transfer is outside both variants' native timers. Artificial transfer limits
are removed per user instruction, and the large model remains resident on B300.

## Full-model result and decision

The unprofiled, independent-process measurements are:

| Order | Variant | Evaluation (s) | Host encoding (s) | Refresh (s) |
| --- | --- | ---: | ---: | ---: |
| A0 | Baseline | 265.48538 | 144.95704 | 46.39623 |
| B1 | Inverse-FFT plan | 235.24677 | 114.36953 | 45.02582 |
| B2 | Inverse-FFT plan | 234.43779 | 114.37451 | 45.07949 |
| A3 | Baseline | 266.95711 | 145.45311 | 46.46813 |

| Mean metric | Baseline | Candidate | Reduction |
| --- | ---: | ---: | ---: |
| Full evaluation | 266.22125 s | 234.84228 s | **11.79%** |
| Evaluation minus refresh | 219.78907 s | 189.78962 s | 13.65% |
| Host encoding | 145.20507 s | 114.37202 s | 21.23% |
| Refresh | 46.43218 s | 45.05266 s | 2.97% |
| Setup | 74.96221 s | 76.57176 s | −2.15% |
| Complete container run | 365.59117 s | 342.44765 s | **6.33%** |
| Evaluation / four generated tokens | 66.55531 s/token | 58.71057 s/token | 11.79% |

Host encoding is a nested timer, so these rows are not disjoint costs.
"Evaluation minus refresh" is an arithmetic difference, not an independently
instrumented kernel category. Complete run time spans the GPU-availability
check and Docker invocation through process exit, including startup, setup,
evaluation, validation/output and teardown; it excludes time waiting for the
campaign lock and external transfers. Setup varies by process, and the measured
full-run saving is smaller than the evaluation saving. The patch does not
change refresh arithmetic; the small refresh-time difference is not evidence
of a separately optimized refresh circuit.

All four runs pass both unchanged `0.001` gates. The maximum error against
the exact reference is **4.70755e-5** and against the polynomial reference
**5.72751e-7**. Generated IDs agree in every run. Each evaluates 7,814 live DAG
nodes, performs 78,369 host encodes, 11,540 ct-ct products, 135,279 ct-pt
products, 66,464 ordinary rotations and 484 physical bootstraps. GPU ring
switches remain 242 up and 484 down; no evaluation/debug decryption is added.
Peak RSS remains about 26.29 GiB. Parameters remain the previous experimental
`security=not-set` configuration; this result does not qualify a 128-bit setup.

**Adopt as an optional OpenFHE dependency patch.** The largest full-run saving
is consistent with the CPU inverse-FFT mechanism: host encoding falls by
30.83 seconds, while evaluation falls by 31.38 seconds. This is one frozen
prompt and two full samples per variant, not a general throughput or statistical
significance claim. The noisy small experiment is retained; further prompts,
longer horizons, different CPUs and full Mamba-2 timing remain separate work.

## Reproduction, checks and retained state

Use the [shared experiment tools](../experiments.md) to verify the public
manifest and compare samples under explicit numerical/count/argument gates.
These are offline checks, not a GPU rerun. The
[result directory README](../../results/b300/2026-09-26/nsight-ifft/README.md)
maps commands, profiler summaries, source snapshots and large retained artifacts.

The final patch reproduces the measured candidate source byte-for-byte.
All 37 core-archive members are checked; only `dftransform.cpp.o` changes.
The final CMake qualification build and both final probe variants pass the
same FFT/encoder golden streams after the timed model controls. The repository
check suite passes **292 tests, 87.60% coverage and 21 native C++ contracts**.

Completion hooks serialize GPU work and allow local packaging/checks while
jobs run. All 25 study containers are stopped and removed after recording their
exit states. Intermediate object/build directories and the downloaded package
duplicate are removed; profiler reports, golden streams, source snapshots,
binaries and the task-local profiler CLI remain on B300 with recorded hashes.
No shared GPU jobs, host drivers, clocks or global permission settings are changed.

The remaining measured CPU candidates are `FitToNativeVector` and the scaling/rounding
work in `Encode`; launch and synchronization overhead also remain visible in
the baseline trace. They are outside this one-mechanism implementation and
need a fresh profile and their own exactness/model controls before promotion.
