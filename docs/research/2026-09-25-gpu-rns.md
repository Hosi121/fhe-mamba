# Compact plaintext preparation with GPU RNS expansion

This study implements one follow-up to [S2C-first refresh](2026-09-25-s2c-first.md).
It reduces ordinary evaluation work while retaining that circuit, both residual
correction passes, and the exact ciphertext-level schedule. The full twelve-layer
comparison improves **750.4135 → 618.9536 s (17.52%)**. Ordinary evaluation falls
**501.0506 → 381.0208 s (23.96%)**, with unchanged accuracy gates and generated
tokens. The candidate is adopted as an opt-in path, `--gpu-plaintext-rns`.

## Mechanism and correctness

The existing encoder computes one inverse CKKS FFT, then expands its rounded
coefficients into every residue-number-system (RNS) tower on the CPU. The prior
S2C-first run spent 183.138 s in host encoding, inside 747.629 s of total native
evaluation. Avoiding all of that time would save at most 24.50%; FFT, dispatch,
transfer and GPU conversion costs remain in the candidate.

The new path calls the same pinned OpenFHE encoder with just the first modulus
q0, then uploads one N-word coefficient vector. A CUDA kernel lifts each residue
to its signed integer and reduces it into each GPU tower. The existing GPU NTT
then runs. Its output must equal every residue from the full OpenFHE encoding.
This changes where public coefficients are expanded; ciphertext arithmetic,
model polynomials, CKKS parameters and the refresh circuit remain unchanged.

For scale sigma and s input slots, every exact inverse-transform coefficient is
bounded by `sigma * sum(abs(values)) / s`. The compact path requires that bound
plus one to be below `q0 / 4`. This leaves a factor-two margin below the signed
lift boundary q0/2 and keeps these 60-bit-modulus inputs below OpenFHE's large
coefficient approximation branch. The norm includes zero-padded slots; opposing
signs cannot cancel in this bound. After the unchanged FFT and rounding, the q0
residue identifies the same signed integer used by every other modulus.

For each target modulus q, the kernel uses `m = floor(2^64 / q)` and
`floor(magnitude * m / 2^64)` to estimate the quotient. For a 64-bit magnitude
this underestimates the exact quotient by at most one. One conditional
subtraction produces the exact residue; a negative coefficient maps a nonzero
residue r to q-r. No floating-point arithmetic occurs in this conversion.

The path currently admits full packing, degree-one plaintexts, FLEXIBLEAUTO,
one GPU and the pinned 64-bit word layout. High coefficients, higher scale
degrees, smaller slot counts and a one-tower target retain the full encoding.
These are dispatch conditions, not relaxed numerical tolerances.

The loader uses a private reusable staging allocation. It synchronizes the
upload before the limb streams read that vector, waits for expansion before a
temporary workspace can be freed, and completes the existing NTT before return.
Inputs remain owned by the caller. Compact CPU objects are staging representations;
they must use this loader, not a generic CPU encryption/serialization path.
The verification helper reads back a complete GPU polynomial.

The pinned OpenFHE commit and encoder hashes are recorded in
[openfhe-source.json](../../results/dgx/2026-09-25/gpu-rns/openfhe-source.json).
No FFT, rounding or model approximation is reimplemented. The S2C-first backend
source overlay is byte-identical to the preceding study (91 checked files).
The separate rebuild's static-library hash differs and is recorded, along with
both executable hashes and build options.

## Small checks

Spark GB10, CUDA 13.0, CPU affinity 15–19, ring degree 65,536, 32,768 full slots,
depth 44, 59-bit scaling and first prime size 60 match the prior study. The
existing `security=not-set` qualification remains. No broader parameter or
long-context qualification is implied.

Three independent probe processes cover real/uniform-ternary with one and four
CPU threads and complex/sparse-ternary with four threads. Each checks 240 complete
RNS polynomials against stock OpenFHE, at six levels, two slot counts and two
scale degrees. Patterns include signed zero, positive/negative masks, both sides
of the conservative bound, large coefficients, tiny values and an isolated
negative impulse. All **720 cases** match exactly: **105 compact** and **615
fallback** cases. All **27 encrypted multiplication/addition checks** pass the
unchanged 1e-6 gate; the observed worst error is about 2.31e-12.

Warm preparation times include CPU encoding and synchronized GPU upload/NTT.
Each level uses ABBA order and eight timed samples per block after one warm-up.
These are standalone preparation times, not model inference speedups.

| Consumed level, real/four-thread probe | Existing, ms | Compact, ms | Reduction |
| --- | ---: | ---: | ---: |
| 18 | 5.7052 | 1.5147 | 73.45% |
| 26 | 4.2025 | 1.4049 | 66.57% |
| 34 | 2.7285 | 1.2919 | 52.65% |

The CPU encoding component falls from 5.0420/3.7446/2.4770 ms to
1.1375/1.1376/1.1404 ms at those levels. Host preparation of eligible plaintexts
therefore loses its dependence on the number of RNS towers; GPU work still
depends on that number.

The Mamba-2 configuration probe validates shared plaintext machinery. This study
does not switch or benchmark the legacy Mamba-2 full executor.

## Prefix and full inference

The released S2C-first executable is the baseline. The candidate uses the same
S2C-first flag plus `--gpu-plaintext-rns`. The fixed checkpoint, public coefficients,
payload and two 0.001 output gates remain unchanged. Model/wrapper multiplication,
rotation and refresh counts must match, in addition to generated token IDs.

The independent ABBA one-layer prefixes average **38.3566 → 30.8898 s**, a
**19.47% reduction**, with the same schedule and [6864, 6864] token IDs. The
full twelve-layer pair uses five encrypted evaluations and four generated IDs
[315, 279, 1614, 315], matching both references.

| Full native evaluation component | Baseline, s | Candidate, s | Reduction |
| --- | ---: | ---: | ---: |
| Total | 750.4135 | 618.9536 | 17.52% |
| Ordinary evaluation, total minus refresh | 501.0506 | 381.0208 | 23.96% |
| Refresh | 249.3629 | 237.9328 | 4.58% observed |
| Host encoding, included above | 183.5528 | 65.2434 | 64.46% |
| Linear operations, excluding refresh | 156.0860 | 97.9359 | 37.26% |
| Routing, excluding refresh | 204.4053 | 148.1739 | 27.51% |
| Polynomial operations, excluding refresh | 124.1780 | 120.3495 | 3.08% |

The new encoding path handles 46,977 preparations, with 2,679 fallbacks (94.60%
eligible). Its counter records 426,638,311,424 fewer logical host-expansion and
upload bytes, cumulatively. This is not a measurement of physical DRAM traffic
or peak memory: process RSS remains **26.2066 GiB** in both runs.

Both runs execute 484 backend bootstraps, 1,335 logical refreshes, 12,005
ciphertext products, 106,541 plaintext products and 62,969 rotations. The
refreshed level, refresh ceiling, batching and frontier decisions also match.
The refresh implementation is unchanged; this single pair does not establish
that the candidate causes the observed 11.43 s difference in refresh timing.
The adoption case rests on the 120.03 s reduction in ordinary evaluation,
supported by the separate preparation probes and ABBA prefixes.

Maximum errors against the exact reference are **4.72544e-5 → 4.70075e-5**;
against the frozen polynomial reference, **4.14178e-7 → 5.00072e-7**. Both are
below the unchanged 0.001 gates, with no non-finite values or intermediate
evaluator decryptions. Fresh keys explain why exact plaintext preparation does
not require identical decrypted floating-point output between processes.

Native evaluation includes preparation, upload and client feedback inside the
evaluation loop; setup, parsing and final client validation are outside it.
Process wall time is **791.4642 → 660.2934 s**. Category totals subtract nested
refresh timers; host encoding is already included in those categories.

This is one full process per variant on a fixed prompt and checkpoint. The
prefix controls support the direction of the result; no statistical-significance
or arbitrary-prompt claim is made. The single-candidate stopping rule is complete.

## Reproduction and validation

The [evidence collection](../../results/dgx/2026-09-25/gpu-rns/) contains the
source archive, exact commands, warm-up and timed samples, payload manifests,
numerical gates and executable hashes. The job controller runs full inference
only after exact-RNS checks and successful, faster prefixes. Builds finish before
timed comparisons start.

The Spark build script enables the optional native CUDA target. For a custom
build, add `-DFHE_STAGE0_GPU_RNS=ON` and the matching CUDA architecture. Add
`--gpu-plaintext-rns` to the packed executable or `experiments/run_packed_probe.py`;
retain `--s2c-first --planned-refresh --batch-refresh --frontier-refresh` for
this comparison. Without the CUDA target, the new flag is rejected before
payload evaluation. Omitting the flag retains the existing preparation path.

Local validation passes **290 tests**, including **20 C++ contracts**, with
87.60% Python coverage. Both Ruff checks, all native GPU-linked targets and the
older-backend build pass. The older build rejects the flag without reading a
payload. After full inference, both existing plaintext regression probes pass:
320 exact-RNS, 324 shared-policy, 320 moved-coefficient and 640 borrowed-RNS
checks in total, with maximum encrypted error 2.39e-12. These counts cover
different checks and are not presented as disjoint inputs.

The delivered native implementation matches all 85 archived source files.
Seventeen canonical dependency hashes remain unchanged. Build failures are
retained separately from the successful final build; an initial CUDA header
exposure conflict was fixed before any timed run. The collection records the
adoption decision and cleanup of study-owned build trees, preserving raw results,
source archives and the three measured executables on the DGX.
