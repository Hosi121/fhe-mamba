# Mamba-3: complete SISO mixer under CKKS

The first implementation runs a synthetic Mamba-3 mixer from encrypted input
projection through output projection, including all nonlinearities and carried
state. It shares one formula across exact, polynomial and packed arithmetic.
See the [usage and reproduction guide](../mamba3.md).

## Measured scope

The fixture uses public random weights (seed 19), model width 32, inner width
64, two heads of width 32, state size 16, one B/C group, rotary fraction 0.5
and no optional output normalization. Each state tensor fits in one ciphertext.
128 independent calibration inputs define the polynomial domains; evaluation
inputs are held out. The export rejects domain violations and missing fits.

FIDESlib on DGX Spark GB10 evaluates the circuit at ring dimension 65536,
1024 real slots, depth 44, scale 59 and `security=not-set`. Every listed error
includes both mixer outputs and all four carried states. Decryption happens
only after evaluation. The test gate is maximum absolute error `0.001` against
both the exact and polynomial references.

| Sequence | Setup | Encrypted evaluation | CKKS vs polynomial | CKKS vs exact | Peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| [4 steps](../../results/dgx/2026-09-24/mamba3-siso/tokens4/native.json) | 15.10 s | 102.68 s | 7.19e-13 | 7.72e-8 | 16.57 GiB |
| [8 steps](../../results/dgx/2026-09-24/mamba3-siso/tokens8/native.json) | 15.35 s | 195.71 s | 8.75e-13 | 1.58e-7 | 16.57 GiB |

Both runs pass with zero evaluation decryptions and zero bootstraps; the short
carried-state dependency chain fits the available levels. The setup still
prepares bootstrap keys. Timings are one run per sequence, not a performance
comparison against the much larger trained Mamba-2 workload.

The generic executor's [separate refresh test](../../results/dgx/2026-09-24/mamba3-siso/refresh/native.json)
multiplies an encrypted vector by public ones 45 times, forcing an automatic
refresh without changing the intended value. It passes with two physical
bootstraps, maximum error `4.23e-7` and evaluation time 1.71 s (setup 15.36 s).
This validates refresh arithmetic, not long-context Mamba-3 accuracy. Reproduce
its payload with `experiments/export_packed_refresh_probe.py --output <dir>`
and use the same bounded native runner.

## Independent formula check

[Upstream CPU-reference parity](../../results/dgx/2026-09-24/mamba3-siso/upstream-parity.json)
uses state-spaces/mamba revision
`e9594ce1c732d97440f0332fdc43170a2294dbfa`. The original preprocessing, rotary
reference and fused-step reference functions are loaded from that checkout.
Four cases combine both rotary fractions and both output-normalization modes,
with nontrivial B/C biases, two batches and seven carried steps.

Maximum output difference is `2.30e-10`; maximum state difference is `4.14e-10`.
The `1e-7` comparison tolerance accounts for upstream's float32 A preprocessing;
our mathematical oracle retains float64. This does not test the official fused
CUDA kernels on GB10.

## Implementation decisions

Architecture dispatch allocates a distinct Mamba-3 state instead of assuming
every mixer has a convolution FIFO. `TensorOps` supplies the shared linear,
normalization, readout and nonlinear boundaries. `PackedProgram` lowers public
shapes and weights to architecture-independent instructions; the native
executor has no Mamba-3-specific recurrence. The established Mamba-2 native
kernel remains its optimized backend.

The initial generic gather lowering emitted excessive rotations for broadcast
operations. That exploratory run was manually stopped before completion;
its [log](../../results/dgx/2026-09-24/mamba3-siso/generic-gather-aborted.log) is retained.
Broadcasts now place compact blocks and replicate them with doubling rotations.
No matched performance improvement is claimed from the incomplete run.

## Evidence and limits

[Recorded artifacts](../../results/dgx/2026-09-24/mamba3-siso/) include the exact
compressed programs, fixtures, polynomial recipes, logs and raw measurements.
[Provenance](../../results/dgx/2026-09-24/mamba3-siso/provenance.json) binds the
binary, compiled source files, reproduction sources and linked OpenFHE libraries.
The final Python exporter regenerated the 8-step program, fixture and manifest
byte-for-byte. The 4-step result predates the generic runner; the 8-step and
refresh results additionally have runner records with hard timeouts and hashes.

To replay a frozen payload, copy its result directory, decompress
`program.txt.gz` to `program.txt`, and give that directory to
`experiments/run_packed_probe.py`. The manifest's original uncompressed hash
must match. Existing native result files are not overwritten by the runner.

This is SISO mixer support with random weights. It does not establish MIMO,
full-checkpoint encrypted generation, language quality, long-context stability
or 128-bit security. Polynomial fit errors are sampled on a grid and are not
interval certificates. Public refresh bounds apply to the frozen synthetic
probe, not arbitrary private inputs.
